# M3 本地模拟审批验收

本轮交付审批处理；模拟执行器尚未接入。沿用原桌面布局。

## 启动新版

退出旧的 RetailPilot 窗口，在项目根目录执行 `bun run retail:start`。当前源码已构建；若另行修改代码，先执行 `bun run retail:build`。

## 正向流程

1. 进入“经营分析”，载入演示数据，配置可用模型连接并完成一次模型调查。
2. Reviewer 必须通过，选择约束可行的方案，生成决策草稿。建议先验证毛利场景；库存方案若有到货前缺口会被阻断。
3. 核对前后值，保存并“提交模拟审批”。点击“查看审批”或顶部“审批中心”。
4. 核对具体版本、范围、数据来源、证据、有效期和约束。留空理由时不能处理。
5. 填写理由，点击“批准模拟方案”：应显示“模拟已批准”，保留理由、时间和审计；不会改变价格、库存或广告预算。
6. 返回决策草稿，修改备注并保存新版本：旧申请应显示已被新版本替代，原批准结论仍保留。为新版提交申请后填写理由并驳回，应显示驳回结论。
7. 筛选“全部”，检查两个版本；退出并重新启动，结论、理由和历史仍存在。
8. 导出报告与证据 JSON，检查 decisionHistory 中的 approvalResolution 与 approvalInvalidation。

## 阻断与失效

- 离线规则演示、缺证、Reviewer 未通过、导入 CSV、不可行方案不能提交模拟审批。模型实际输出若为待补证，应先补证，不跳过门禁。
- 草稿有效期为30分钟，演示数据导入超过24小时需重新核验。到期后刷新或处理时显示失效并禁止批准。
- 同业务键导入新快照或规则、报告改变后，刷新或处理时重新检查；发现失效会保存，数据恢复后也不会让旧批准重新生效。
- 旧页面处理新版已替代的申请会被拒绝。重复点击相同结论和理由只保留一份记录；不同结论不可覆盖已有记录。

## 边界与恢复

这是单用户本地模拟审批角色，不具备生产多用户独立审批身份。模型与只读 MCP 无审批权限。批准不会触发执行；下一阶段才实现本地模拟执行、幂等和回执核对。

已有决策库从 v1 增量升级 v2，升级前生成 `<业务库路径>.investigations.backup-v1-<UUID>.sqlite` 一致性备份。保留原草稿、申请及历史；备份用于人工恢复，尚无自动恢复入口。未来版本数据库会拒绝打开。

原生自动验收：`node scripts/retailpilot-m1-e2e.cjs`。它使用隔离配置与本地模型协议响应验证界面和持久化，不代表真实模型推理质量。
