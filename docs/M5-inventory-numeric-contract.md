## 库存数值契约

库存调查的 `summary`、假设、未知项、替代解释和方案理由改为定性文本，模型 `observations` 必须为空；含阿拉伯/全角数字或经营中文数词的输出被拒绝并按原预算纠正。Reviewer 理由也使用定性契约，不复述数量。

代码核验冻结字段与派生指标、四种工具返回、证据 ID、冻结 Case 以及条件方案之后，生成现存、占用、即时可售、在途、销量、窗口、日均、覆盖天数、交期、及时在途、目标库存和补货草稿量。工具缺失、范围错配、指标或方案篡改时不生成报告。零/缺销量保持补证，不能写成零天覆盖或自动补货。

日均销量和覆盖天数保留整数分子/分母，近似值明确标注；件与天分开，不能把在途算成即时可售。目标库存改用 BigInt 分数向上取整：`ceil(7/3×27)` 必须为 63，原浮点链路可能误取为 64。规则和交期假设没有因此变成需求预测。

库存数值审计随报告持久化与导出；Reviewer 看到的事实观察与保存版本一致。报告通过不改变方案硬约束：默认交期超过库存覆盖时，补货方案仍不可执行。真实采购、到货或收益不会由报告生成。

七项新增领域测试覆盖模型数字表面、事实单位/分数、工具/身份/方案篡改、零/缺销量、浮点取整、复核与持久化一致性及更正预算。真实模型评测契约升级为 `retail-live-eval-v4`，新增库存事实核验评分；Skill 为 1.4.0。尚不能用旧 v3 的 15/15 证明新 v4 模型质量通过。

## CI 修复

- CI Bun 从 1.3.10 对齐本机与打包验证的 1.4.2。GitHub 运行 `39107658382` 已确认冻结依赖安装通过；无需放开 frozen-lockfile 或重选依赖版本，原锁文件未变更。
- 后续云端失败暴露出 Unix 文档工具脚本没有可执行位；修复 Git 的 100755 模式，不关闭文档工具测试。
- 恢复 `lint:i18n:coverage` 引用但缺失的脚本，使用 TypeScript AST 检查实际翻译调用的静态键，忽略注释和无关调用。动态键及硬编码文案明确不在本项证明范围内。
- 实际检测发现首次启动的两条经营分析文案缺失，补齐全部七种语言；键一致性、排序和静态键检查通过。
- CI 新增领域回归、隔离推理 telemetry、覆盖检查器自测和真实 MCP 回归，保留原上游验证链。

本机共享配置测试曾受到沙箱临时文件原子重命名权限影响；解除该权限限制后的整套重跑又出现一次进程型测试五秒超时。这些失败需保留，不能合并成“全项目所有测试通过”；后续记录应分别说明运行环境、超时配置与云端结果。
