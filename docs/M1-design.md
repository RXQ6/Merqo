# M1 设计与范围

经营工作台默认展示数据与规则结果，不以通用聊天页代替场景入口。通用 Agent 作为单独入口保留。

视觉采用冷灰背景 #f3f6f9、深蓝导航 #183345、白色数据面板 #ffffff、青色操作 #216b73、红色毛利风险 #b33e39、琥珀色证据缺口 #9e691d。Segoe UI 与 Microsoft YaHei 承载业务文字，数字用等宽数字排版。布局为左侧经营导航、上方业务范围与指标、中部商品快照表、右侧证据抽屉；不用装饰性图表或无业务意义的指标卡堆叠。

数据单位是一条店铺、渠道、SKU、日期快照。列表中的“商品收入”按件计算，指标中的收入按净成交件数汇总。公式为：商品单价 − 商家券 − 商家满减 + 已确认的平台额外结算补贴；商品毛利减商品成本。不含运费、佣金与广告。平台补贴指额外入账部分，禁止把已含在售价中的补贴重复填入。商家承担的补贴需先归入商家优惠，本版拒绝直接计算。

同批次重复业务键隔离，重复文件与映射幂等；新批次相同业务键成为当前快照，历史批次及原始行保留。演示数据和用户导入永远按来源分开查看，不混入同一合计。缺成本、补贴归属未知、SKU 规格冲突不计入收入和毛利合计，显示完整性分母。

领域 API 只接受白名单操作，通过专用 contextBridge 方法进入主进程；Workspace 由顶层 webContents 的已注册窗口确定，renderer 无法指定数据库路径或跨 Workspace ID。子进程没有执行价格、预算、补货或任意 SQL 的接口。每次请求启动独立 Bun 工作进程，SQLite WAL 与事务保证落盘，成本是每次查询有启动开销，后续数据量扩大再做常驻服务。

当前仅支持本机 Workspace、CNY、UTF-8 CSV、2 MB 文件、每来源最多 10,000 条当前快照。静态导入不代表实时监控或已验证的数据新鲜度。20% 为版本化演示规则，本阶段不提供规则编辑器。Agent 调查、方案、审批和执行不属于本轮完成声明。
