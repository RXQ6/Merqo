# Merqo：PRD 完成情况与场景化改造报告

日期：2026-10-18（北京时间）

核查基线：`ef4d390ce3490fc513e701f83623d8528f1f2e86` / `v0.1.0-beta.2`
方法：对照原始 PRD、当前源码、归档评测和安装验收。本报告未重新调用付费模型或重跑测试，数字引用已归档结果。

## 1. 结论

**PRD 尚未全部完成；场景化改造已经实际落地，达到可运行、可展示、可验证的本地零售经营预览版。**

项目已从通用聊天工作台扩展为三场景经营工作台：有领域数据、确定性计算、异常、只读调查、证据、方案、Reviewer、本地模拟审批与执行、复盘和 Case。场景化实现存在于领域代码、工具权限、业务账本和页面中，不只是提示词或界面名称。

正向审批/执行闭环限定为合成 demo：用户导入 CSV 目前仅供分析，不能因字段齐全就取得模拟审批/执行权限。历史 Case 也按 demo 与作用域限制检索。这是当前明确的产品边界，不能把演示闭环说成任意导入数据都能完成处置。

但当前主要支持**同口径静态快照分析、条件算术和模拟处置**。它还不能完整回答真实业务中的“为什么下降、实际该改什么、实施后到底是否有效”。三场景跨来源联合诊断、部分 PRD 数据与动作语义、完整性能/安全验收仍有缺口。发布了安装包，也不等于 P0 门禁全部通过。

完成情况应分三层描述：

| 层次 | 当前判断 |
| --- | --- |
| P0 本地原型 | 主干闭环已实现，多项限定范围验收已通过；仍需收口业务语义和质量证据 |
| P1 外部试点 | 未形成“真实只读系统＋测试环境写 Adapter＋可信身份”的验收闭环 |
| P2 生产化 | 未完成组织权限、多租户、更多平台和集中运维等建设 |

原 PRD 明确允许 P0 使用合成数据、CSV 和模拟系统，因此**缺少真实平台接入不应单独算作 P0 未完成**；它属于 P1。也不建议给出“完成 90%”之类数字：目前没有逐条签收的统一权重和分母。

依据：[原始 PRD](PRD-v0.1-2026-10-15.md)第 4、5、6、12、13 节；[本机验收](M5-local-acceptance.md)。

## 3. 三个主场景做到了什么

### 3.1 促销与毛利

**已有：**商家券、满减、额外平台结算补贴、商品成本与毛利；缺成本/承担方不明时补证；一层组合装、免费赠品、单一会员分组、可售参考报价；减券条件测算、模拟审批执行、复盘及 Case。毛利查询已具备服务端分页与精确范围汇总。

**实际边界：**

- 当前分析的是商品毛利，未将运费、佣金、广告、税费全部纳入净利润。
- 券和满减是已整理的单件快照字段，尚不是通用订单级门槛/分摊规则引擎。
- `reduce_coupon` 修改模拟商家券，不是任意修改 SKU 标价。应补动作或明确修订 PRD；二者不能混称。
- 不证明“促销导致销量/利润下降”；当前模型通过的是快照描述和条件算术。

### 3.2 销量下降与缺货风险

**已有：**相邻等长窗口销量比较、可售库存、覆盖天数、交期、在途 ETA 和补货缓冲；在途不当作现货；补货草案与模拟请求；交期超过覆盖时拒绝假装补货能消除到货前缺口。

**实际边界：**

- 覆盖天数基于既有窗口销量，不是完整需求预测。
- 没有证明销量下降由缺货造成，也没有完整流量/活动/缺货时长证据。
- 尚无完整多仓调拨、MOQ、整箱、采购预算、供应商产能等约束求解。
- 模拟补货请求受理不代表采购完成或库存到账。

### 3.3 广告回报下降

**已有：**相同归因口径的 ROAS、花费/归因收入、点击/转化、前后窗口；广告数字由代码生成并核验；降低预算的条件测算、模拟批准执行和回读。

**实际边界：**

- 降预算方案是效率不变的条件算术，不证明 ROAS 会改善。
- 只读广告上下文主要来自广告记录，尚未完整联合商品毛利、实时库存、自然流量与活动证据。
- 缺退款回流、转化延迟成熟度、增量归因/对照，不支持把 ROAS 当净广告 ROI。

源码依据：[业务数据与请求 Schema](../packages/retail-domain/src/operations.ts)、[库存/广告计算](../packages/retail-domain/src/signals.ts)、[场景工具与调查](../packages/retail-domain/src/signal-investigations.ts)、[冻结工具范围](../packages/retail-domain/src/readonly-tools.ts)。

## 7. 建议增加的具体业务场景

### 第一组：在现有三场景内深化，价值最高

| 建议场景 | 关键新增数据/逻辑 | 预期行为与可验证标准 |
| --- | --- | --- |
| 广告花费继续，但 SKU 即将断货 | Campaign→SKU 映射、可售库存、ETA、归因窗与流量 | 先展示库存风险与归因缺口，再比较观察/限额等方案；映射错或数据不同步不得建议跨对象动作 |
| ROAS 不变，但促销后利润空间收窄 | 同口径毛利、券、赠品、成本、广告花费、费用是否齐全 | 并列 ROAS 与可计算的贡献口径；费用未知则明确不能计算净 ROI，不得输出“投放盈利” |
| 库存覆盖不足，但常规补货来不及 | 供应商交期、到货可信度、缺口天数；后续可选调拨来源 | 正确拒绝“补货即可解决”；先给缺口与补证，再在有数据时比较调拨/加急/限促，不编造可用库存 |
| 活动结束后销量下降 | 活动日历、价格变化、可比窗口、流量/转化 | 区分活动回落与缺货假设；仅有下降和低库存时不能断言缺货因果 |
| 会员价＋券＋赠品造成毛利跌破阈值 | 同会员分组、优惠规则、赠品成本及完整身份 | 确保价替换一次、成本扣一次、互斥冲突补证；输出可核验条件方案，不混算多个分组 |
| 广告转化迟到或退款回流 | 归因成熟时间、原订单/退款关联、源水位 | 未成熟窗口标记暂不可比；更正后追加版本，不因刚抓取就当作完整最新数据 |

这些场景都可以先用合成数据和 CSV 建立可重放契约，不必等真实 API。每项至少包含正常、风险、证据不足、范围冲突四类输入，并增加模型夸大因果或越权的负例。

### 第二组：由试点业务决定，不建议全部立刻开发

- **多仓调拨与补货约束**：库存可转移、出入库时延、MOQ/整箱、采购预算；验收“建议数量可行”而不只是算出一个数字。
- **滞销/临期清理**：库龄、保质期、批次、折扣约束及缺货风险；适用于有批次商品的门店。
- **退货与贡献利润复盘**：订单级收入/退款/佣金/运费归属，先定义商品毛利、贡献利润与净利润的不同口径。
- **价格/竞品对比**：同规格与到手价、运费、会员/地域限制、可售状态；先做可信导入，不先上跨平台自动采集。

以上是新增产品建议，不是已经完成的能力，也不全部属于原 PRD 的 P0 必须项。

## 8. 推荐实施顺序与结束条件

**第一阶段：P0 收口。** 先完成 A1–A5 和 PRD 差异决策。出口是：干净 checkout 可安装验证、九项质量门禁逐项有证据、三场景完整 UI 回放、无未处置的安全失败、性能声明与实际覆盖一致。需要外部机器的兼容性项目单列等待，不假填通过。

**第二阶段：三场景联动。** 优先做“投放遇到缺货”和“ROAS 与毛利联查”两个场景，再做活动回落解释。出口是：每个结论绑定跨来源证据与时间范围，缺一项能正确补证，至少两个条件方案可核验，未证实原因不写成事实。
