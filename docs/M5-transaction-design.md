# 交易与退款数据契约

2026-10-19，实现前契约。独立事件账本补充 D03/C04，不把已有 sold_qty 快照解释为订单明细，也不自动替换已冻结的调查。

一行是 `ordered / paid / shipped / refunded` 事件，包含独立来源、事件 ID、订单和行 ID、店铺、渠道、SKU、规格、币种 CNY、原订单时间、事件发生时间、数量、金额、已分摊商家优惠和平台结算补贴。时间须带偏移，查询按 Asia/Shanghai 左闭右开日窗；所有金额是整数分。

每个订单行一个下单、一个全额支付事件；允许分批发货、多次部分退款。分次支付、取消、换货、多币种、自动订单级优惠分摊本版不支持，必须先由来源明确行级分摊。支付结算额 = 原行标价总额 − 行级商家优惠 + 明确平台补贴。退款金额是商家结算撤销额；退款数量是财务退款件数，不代表实物已退回或恢复库存。仅退差价可填数量 0；累计退款金额/件数不得超过支付，累计发货件数不得超过支付。

来源+店铺+渠道+订单+行确定实体，同一实体的 SKU/规格/原订单时间必须一致。事件 ID 在来源/店铺/渠道范围唯一；同事件重导入不重复记账，同 ID 不同内容拒绝覆盖。缺原订单/支付、时间倒置、超额退款、金额等式不成立均拒绝；整个事件导入原子提交，防止孤立链。来源元数据为操作者声明，不能构成真实平台认证。

“事件发生期”按每条事件发生时间计入数量和金额，退款在发生期冲减；“原订单归属期”选择原订单时间落入窗口的整条事件链，并展示当前已导入事件的累计结果。后者是截至当前导入的订单队列视角，不能冒充该历史期间当时已知的财务结果。两种视角均展示下单/支付/发货/退款件数，支付、退款和保留结算额；不宣称净利润。

页面位于经营分析 → 数据管理 → 交易与退款，支持模板、演示、预览、来源声明、原子导入、日期/来源/归属视角、汇总和分页明细。此账本独立于模拟执行系统，任何导入不能授予写入资格。
