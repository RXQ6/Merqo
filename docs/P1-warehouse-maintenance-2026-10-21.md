# 仓库预占、盘点与调拨异常

2026-10-21，开发版，本地人工声明账本；不回写真实 WMS，不修改旧库存快照或交易金额。

## 使用入口

经营分析 → 库存与广告 → 仓库收发存与调拨。下载“预占与释放示例”或“库存更正示例”，导入 JSON，预览后确认；查询支持来源、店铺、仓库和北京时间截止日期。结果新增预占数量、可分配数量、预占明细、调拨丢失/退回及最近30条事件审计。表格最多100库存桶/预占/调拨，汇总覆盖完整筛选；最近20份工作空间回执不受筛选限制。

## 事件与约束

沿用不可变事件 ID、预览哈希及原子确认。文件8 MB、单次2000事件、账本50000事件。老事件不变，新事件追加；旧预览遇到其他导入或来源证据变化即失效。同时间按照固定业务阶段排序，再按事件ID排序；不同先后含义应提供可区分时间。

| 事件 | 必需声明 | 数量影响 |
| --- | --- | --- |
| `reserve` | 唯一 reservation_id、人工 order_ref、明确仓库商品批次 | 仅可售且效期已知未过期；预占不超过未预占数量，现存不变 |
| `release` | 同来源店铺预占ID及相同库存桶、至少10字说明 | 部分或全部释放剩余预占，现存不变；已过期仍可释放 |
| `shipment` | 原 shipment_ref，可选 reservation_id | 关联预占时同时扣现存和该预占；未关联时只用未预占数量 |
| `inventory_count` | 原 expected_quantity、实盘 quantity、至少10字说明 | 原数量须匹配；不能把现存调低到预占以下，短缺须先核查预占 |
| `expiry_corrected` | 原 previous_expires_on、新 expires_on、quantity=0、说明 | 对同来源店铺SKU规格批次全仓生效，不改变数量；可将新值撤为未知 |
| `state_changed` | 原 state、新 to_state、数量、说明 | 同仓同批次数量守恒，不使用预占；报废不允许恢复，转可售须效期已知有效 |
| `transfer_loss` | 原调拨ID、原调出库存桶、数量、说明 | 只结减在途，不增加目的仓或恢复源仓 |
| `transfer_return` | 原调拨ID、原调出库存桶、数量、实际回仓说明 | 结减在途并加回原仓；这是人工实际退回确认，非点击取消即还库存 |

调拨到仓+丢失+实际退回累计不超过调出数量，三者共享剩余在途上限。已知效期在普通发货/调拨中不能被更改；显式更正之后，到仓使用更正后的效期。采购到货等原始来源若仍声明冲突效期，新入库仍拒绝，不能用仓库更正静默改写采购凭证。

可分配 = 效期有效的可售状态现存 − 剩余预占。正数库存效期未知时仍未知；过期时可分配为0，原预占保留可审计。历史查询按截至当日的事件重放，不把之后的更正倒灌到过去。

## 例子

- 预占：期初10 → 预占6 → 释放2 → 关联发货3；现存7、预占1、可分配6。
- 更正：期初10 → 实盘9 → 2转隔离 → 更正效期 → 调出3 → 丢失1 → 实际退回1；可售现存5、隔离2、剩余在途1。

## 边界

订单引用、盘点、质量转换、效期和物流说明均为操作人声明，没有平台鉴权或附件真实性证明。不自动超时释放，不自动关联交易订单，不自动拣货/FEFO，不提供真实平台取消或在途赔付记账；盘点差异没有自动生成财务损益。效期更正可影响所有仓库，需自行核实依据。没有改成多人审批系统。
