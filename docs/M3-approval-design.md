# M3 审批处理切片设计

范围：本地模拟待审批列表、详情、批准/驳回、时效与版本/证据校验、审计与重启恢复。本轮不实现模拟执行器。

## 数据与状态

决策库从v1增量升级v2，保留草稿、版本、申请及事件；升级已有v1库前以SQLite VACUUM INTO生成一致性备份。新增不可覆盖的审批结论（每申请唯一）与失效记录（每申请唯一）。批准绑定request ID、decision/version、action hash、policy、证据/报告摘要和过期时间，不改写申请或旧版本。

有效状态为pending、approved、rejected、expired、superseded、invalidated。新草稿版本使旧申请/批准superseded；过期或证据、规则、报告、参数变化使申请或批准失效；发现后写入失效记录，不能因后续数据恢复而复活。原批准/驳回理由和审批时间仍保留。驳回不授予动作权限。

## 安全与事务

新增IPC approvals与approval_resolve。resolve只接受申请ID、期望版本/动作摘要、approve/reject和非空理由，不接受actor、角色、范围、金额或通过状态。注册的本机窗口由主进程确定Workspace与local-simulation-approver身份；数据工作进程不从renderer解析审批人。P0为单用户角色演示，不保证独立审批人身份，不作为生产授权。

IMMEDIATE事务同时锁定调查库与两个源库，校验申请绑定、当前版本、时间与全部原提交门禁，再原子写结论和审计。并发批准/驳回只有一个结论；同一选择与理由的重试返回原结论，冲突选择/理由拒绝。过期、替代和证据失效即使处理失败也落盘失效记录。列表读取同样对发现的失效做事务性登记。没有approve/execute MCP工具；模型与Reviewer不能批准。

## 界面与验收

沿用桌面主题和两栏布局，新增“审批中心”。待审批筛选、详情显示动作前后值、来源/业务日期/导入时间、假设约束、版本/hash、有效期、审批结论与审计。必须填写理由，按钮仅pending且门禁通过时可用；处理后刷新，保留显式错误与重试刷新入口。声明仅本地模拟批准，不执行业务写入。

验证覆盖批准/驳回与重启、重复提交、并发冲突、过期与时间边界、修订后失效、快照/报告/规则变化、失效不可复活、跨Workspace和身份伪造、v1迁移备份与未来版本拒绝。原生Electron验收实际页面及历史，不把本地协议模型响应当作真实模型推理评测。
