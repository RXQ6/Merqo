# M3 执行批次与结果待确认验收

## 启动及准备

退出旧 RetailPilot 窗口，在项目根目录启动：

```powershell
cd "D:\helson-skills\craft-agents-oss-main\retailpilot-agent"
bun run retail:start
```

在演示来源分别准备广告预算和可行补货两个动作：载入“补货执行演示”的1天交期样例，完成两类模型调查及Reviewer；分别保存草稿、提交并批准。先不要单项执行。默认5天交期风险样例仍应阻断审批，不能为了成批执行绕过约束。

若已有成功执行，不能把原动作重新执行一遍。需要时先走独立补偿，再核对当前模拟前值，保存新版本并重新审批。CSV分析或离线演示不能用于模拟执行。

## 创建与执行

1. 打开“经营分析 → 执行记录 → 执行批次”。
2. 新建批次，选择2至10个同工作空间、店铺和渠道的独立已批准动作，填写说明并保存。每项显示具体版本与前后值；同一目标不能重复选择。
3. 勾选逐项本地模拟确认，点击“继续待执行项”。每项单独提交，展示已确认成功、已确认失败、待执行或结果待确认。批次不是一个新的统一批准，不绕过各项批准。
4. 全部成功后无继续或重试入口。重复请求仅查看原结果，不会重复写入。

## 部分成功

某一项本地写入失败时，其他独立项可成功。成功项保留原回执；修复故障后重新确认，只点击失败项旁“仅重试该失败项”。如果批准已过期、证据或目标已变，重试仍被阻断，应重新调查和审批新动作；原失败记录保留，不能改写旧批次绑定来冒充原批准。

批次不自动回滚成功项。需要恢复时，从成功项的原执行回执另行申请补偿，重新审批及核对。

## 退出、超时与待确认

- 每项先保存执行意图及15秒租约，再执行，再登记结果。执行进程退出或响应丢失后，租约到期显示“结果待确认”。
- 刷新批次查看持久化状态；待确认时禁止继续和失败重试，先点击“查询确认结果”。有效租约尚未结束时不要抢占。
- 找到绑定匹配的原成功回执：确认历史成功，不再次执行。
- 找到本轮失败记录：确认失败，仍需检查当前批准才可手动重试。
- 本地原子账本中没有回执、没有失败记录：冻结旧租约后确认未执行，回到待执行；需要用户重新确认继续，不自动执行。
- 回执绑定异常或无法证明结果：保持待确认，人工核查。不能用按钮强制当失败重放。
- 旧进程恢复后，其旧令牌不能再写入。重启后批次、逐项状态和恢复审计均保留。

正常验收不提供故障注入按钮。原生自动测试在隔离配置内真正退出领取进程，并注入一次本地存储失败，验证待确认→查询确认→部分成功→只重试失败项→重启全过程。

## 记录与边界

报告Markdown/JSON包含关联批次的逐项回执和恢复审计。关联批次可能包括同店铺其他独立调查的批准动作，其记录不是当前调查的推理证据；按原run/approval/evidence hash追溯。

本轮是已独立批准动作的编组，不是模型生成一个多动作综合方案；仅本地模拟。不能凭缺少本地回执判断外部系统没有执行；真实平台Adapter、外部查询协议与生产身份权限尚未接入。不宣称跨平台原子性或exactly-once。

决策库升级v5，v1-v4升级前生成一致性备份，保留批准、执行和补偿历史，未来版本拒绝。完整行业Benchmark、真实模型质量、10万行性能和安装发布门禁仍需后续验收。
