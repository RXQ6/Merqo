# M2 首个切片：促销毛利异常调查

本轮目标：从促销毛利预警记录进入只读调查，保留证据引用、两种方案的确定性测算、串行复核与历史记录。沿用原桌面 AppShell。当前不提供审批、改价、预算调整或补货执行。

## 操作与验收

1. 构建后运行 `bun run retail:start`，从原侧栏进入“经营分析”。
2. 载入演示数据，搜索 `TEA-500`。商品行的“查看”旁应出现“开始调查”。
3. 点击“开始调查”，自动创建模型调查；未配置支持的连接时明确显示失败及配置方向，不生成假模型报告。
4. 在设置中配置 API 模型并设为默认，返回该调查点击“重新进行模型调查”。支持 Anthropic Messages API、OpenAI Chat Completions 兼容 API，以及采用这些协议的本地无认证模型。复用现有连接和凭据存储；本轮不支持订阅 OAuth、云身份或 Responses 协议连接。
5. 等待只读查询、分析和串行 Reviewer。逐条查看观察、假设、替代解释、未知项和证据；点击引用定位工具证据。原始字段是数据，不能授予额外工具权限。
6. 如无可用模型，可明确点击“运行离线规则演示”。页面应标记“离线规则演示，未调用模型”，复核也应标记为规则复核。
7. 比较两个方案：继续观察时单位收入 ¥70、毛利 ¥10、毛利率 14.29%；减少商家券的条件测算将商家券从 ¥20 减为 ¥15，单位收入 ¥75、毛利 ¥15、毛利率 20.00%。售价、成本、满减及补贴不变，不预测销量或收益。
8. 缺成本的记录，其方案金额继续为“待补证”，不能因模型 Reviewer 通过而解除阻断。
9. 从“调查记录”查看历史。退出并重启，冻结快照、来源摘要、工具过程和报告应仍可查看。异常退出中的任务在原 5 分钟期限届满后转为失败，保留过程，支持重新调查；本轮不自动续跑模型。

## 实现边界

- Core：`packages/retail-domain/src/investigations.ts`。运行时 Skill 约束、JSON 决策契约、四个白名单只读工具、引用校验、方案测算和 Reviewer。
- Runtime：主进程 `retail-investigation.ts`。直接推理 HTTP 请求，不创建通用 Agent 会话，不暴露 Shell、文件或通用 MCP 工具。连接及凭据在主进程解析，renderer 不能提交地址、模型凭据或 Workspace 路径。每次请求 90 秒内，整个调查 5 分钟内；最多 12 次调查决策及一次串行复核。仅允许两个并行调查。
- 查询范围固定在启动时选择的店铺、渠道、SKU、日期、来源和快照，不接受模型扩大范围或指定 SQL。查询仅返回该快照的数据质量、SKU 上下文、促销结构和方案测算。
- 持久化：每 Workspace 的 `operations.sqlite.investigations.sqlite`，WAL、IMMEDIATE 事务、同快照同模式进行中任务唯一索引。重复开始复用既有任务；明确重新调查建立新记录。终态及超时任务不接受迟到结果覆盖。
- 证据快照保存在业务 SQLite 中；当前不单独落地证据文件。只读工具已接入本调查循环，但尚未发布独立 MCP Server，不应宣称 PRD 的 MCP 交付项已经完成。
- Reviewer 区分报告复核和执行授权；无论结论如何，都不能写入业务系统。代码决定金额、阈值、证据存在性、缺证阻断和状态落盘，模型只输出解释与意见。
- 当前只覆盖促销毛利场景。缺货风险、广告 ROAS、历史 Case 检索和完整 M2 三场景验收仍待实现。

## 验证方式

`bun run retail:check` 包含独立测算、引用伪造、未知工具、预算退出、缺证、幂等、冻结快照和超时恢复检查。

`node scripts/retailpilot-m1-e2e.cjs` 使用隔离配置验证实际 Electron 页面、preload、主进程、工作进程和 SQLite。模型传输使用本机 HTTP 协议测试服务；它可以证明调用、只读工具循环和 Reviewer 连接，不代表真实模型推理质量。真实模型质量验收需要有效 API 连接，未运行时不得记录为通过。
