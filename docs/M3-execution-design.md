# M3 本地模拟执行切片

> 后续进度：单动作补偿申请、再审批与本地模拟恢复已接入，见[补偿验收](M3-compensation-acceptance.md)。本文保留执行切片当时的范围和验证结果。

保留原桌面主题、导航和两栏布局，新增执行记录，审批详情提供进入入口。模拟状态和原始 CSV/演示快照分表隔离，不修改原分析数据。

批准结论和待执行项在同一事务保存；已有批准通过受校验的读取补建。稳定幂等键绑定工作区、申请、批准结论和动作摘要，本地唯一约束保证一个成功回执。执行由主进程派发本机模拟执行员身份，renderer不能传身份、金额、目标或幂等键；模型/MCP保持只读。

执行前重新检查当前批准状态、版本、证据、规则、时效、计算约束；比较批准时模拟目标版本和前值，防止覆盖其他动作。三类动作分别修改模拟商家券、创建待受理补货请求、修改以历史花费为初值的模拟预算。补货不增加立即可用库存；预算变化不产生收入或ROAS效果声明。

本地同步执行在SQLite IMMEDIATE事务内完成。副作用与回执放入同一savepoint，失败全部回滚，但失败尝试与原因保留。进程在提交前退出则无副作用，提交后响应丢失则按唯一回执恢复；成功重试返回原回执而不再次执行。没有远程写请求，不能据此外推跨系统exactly-once。UI超时视为结果待确认，先刷新账本，不自动重试。

回执保存预期/实际前后值、请求与批准摘要、原证据摘要、模拟资源版本、执行员、时间及本地请求号。执行后读取模拟表核对，后续手动核对独立留痕；目标状态变化标为差异，禁止把旧回执当成当前状态。历史成功不会因批准后来过期而被改成未执行。

决策库增量v3，升级v1/v2前各生成一致性备份；未来版本拒绝。验证包含三类动作、越权、过期、修订、证据变化、目标版本冲突、跨进程并发、崩溃/响应丢失恢复、写入失败回滚、差异核对和原生桌面重启。补偿审批、真实系统权限、多动作部分成功和经营效果复盘不在本切片，不能宣称M3整体完成。
