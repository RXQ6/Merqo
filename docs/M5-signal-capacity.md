# 库存与广告十万行容量验收

2026-10-18，接续 [分页接入](M5-signal-pagination.md)和 [PRD 追踪矩阵](PRD-traceability.md)的 A4/G08。

## 实现范围

- 每类场景、每类来源的当前快照上限从 10,000 提高至 100,000；同业务键替换不占新增名额，越界导入在写批次前拒绝。
- 场景 CSV 的主进程请求契约和文件选择限制对齐 32 MB。预览仅返回前 30 条有效/错误样本，同时保留完整有效、隔离行数。更改字段映射后清空有效数量，必须重新校验。
- 导入和载入演示返回分页结果；不在导入结束时另建全量结果数组。原始 CSV 解析、校验数组仍在内存，本项不是流式 CSV 解析器。
- 查询投影通过源游标逐条构建；规格冲突仍从完整来源范围判断，分页不掩盖跨日期冲突。游标持有一致读事务，结束或取消后释放；独立管理语句，避免提前取消污染 Bun 缓存语句。
- 库存/广告巡检通过游标检查全部选定来源记录，在 SQLite 暂存候选异常，再复核租约并一次性提交。预览最多 200 条，检查总数、异常总数和去重账本覆盖全部输入。毛利来源仍沿用原快照读取。
- 来源和巡检连接的 SQLite 页缓存目标设为每连接 64 MiB，降低大型索引写入时默认小缓存的换页开销；不调整同步、持久化、租约或 worker 超时。这个数值不代表整个进程的内存上限，也未测得峰值 RSS。

## 验证

相关分页、源游标和真实 worker 专项通过；巡检专项 14 项通过，包含游标途中异常、重试原子性和暂存期间被其他进程接管租约。十万行预览专项通过，两类场景各核对 100,000 条有效输入、30 条回包和零隔离；使用生产 worker 的默认超时，未放宽截止时间。

领域与 Electron 类型检查、主进程和界面构建通过。使用真实 worker 评测，不调用模型，不修改用户正在打开的工作空间。

性能入口：`bun run scripts/merqo-signal-performance-eval.ts`。固定每场景 100,000 行、20 家店铺；按生成索引独立构造正常/预警/补证计数预期，分别执行 30 次新 worker 查询，覆盖全范围计数、预警筛选、店铺筛选和深页。机器、缓存、逐次耗时、数据摘要与源码摘要由报告记录。

## 失败与修复

第一批查询 p95 库存 1,272.123 ms、广告 1,298.185 ms，查询子项通过；二十万条巡检超过原 30 秒 worker 期限，因此该批整体为失败。候选异常逐条提交改为批量暂存后仍有超时，本机环境也复现，不能归因于沙箱。分段定位为来源检查/暂存约 17.3 秒、账本提交约 20.1 秒。增大 SQLite 页缓存后，同一数据直接巡检为约 20.4 秒；最终仍以生产 worker 的原 30 秒期限验收，不把直接运行结果冒充 worker 通过。

早期临时目录随命令运行环境回收，后续评测改在项目 `.runtime` 下隔离保存，失败保留数据，支持显式 `--resume` 续测。本轮曾有失败临时目录清理 EBUSY，报告在清理前已写入；后续清理异常不会覆盖业务验收结果。

另有源游标提前取消后的 SQLite 语句复用错误，已用独立 prepared statement 和显式释放修复，取消后再次读取及跨连接更新的专项通过。先前失败日志保留，不合并计为通过。

## 边界与后续

常用分页查询的目标是 p95 ≤ 2 秒；导入耗时包含校验、保存和首次投影构建，需单独列出，不能称为两秒内导入。测量为导入预热后的 OS/SQLite 缓存，每次查询仍启动新进程；本机存在其他开发任务，不作隔离机器或前后性能因果比较。

本项不证明冷磁盘、并发写入、十万行界面绘制或所有错误数据组合均已验收。原始 CSV 及校验数组、毛利巡检的全量读取和大量错误批次的报告传输仍有后续优化空间。PRD 整体门禁、业务时间来源与跨场景证据、完整 UI 失败/复盘路径、安全覆盖及外部兼容性仍须按矩阵处理。

本轮源码尚未推送或发布，新能力不属于已有 beta.2 安装包。
