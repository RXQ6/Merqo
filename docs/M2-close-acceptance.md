# MCP 集成、导出与决策草稿验收

## 启动

在项目根目录执行 `bun run retail:build`、`bun run retail:start`。旧窗口使用已加载的旧代码，须退出后启动新版。当前仍显示RetailPilot名称；原桌面布局与主题沿用。

## 调查与证据导出

1. “经营分析”载入演示数据，分别进入毛利、库存与广告调查。
2. 配置模型时运行模型调查；没有连接可明确运行离线演示。两种模式都经独立MCP读取冻结证据，离线仍明确标注未调用模型。
3. 展开四类工具过程，检查“MCP只读查询”；证据ID和快照摘要应与冻结证据一致。旧历史记录不补造MCP标记。
4. 下载“导出 Markdown”和“导出报告与证据 JSON”。核对runId、source、mode、evidenceIndex、冻结快照、工具trace和Reviewer。模型失败时也能导出已保留的证据及失败原因。
5. 导入同业务键修正，再看旧报告/导出：旧调查证据不被替换，新调查使用新快照。

## 决策草稿与版本

1. 有报告的调查点击“生成决策草稿”，选择条件方案，填写备注，保存草稿。
2. 核对已保存版本的前后值、范围、证据/动作摘要、假设、约束与有效期。毛利TEA方案为商家券¥20→¥15、收入¥70→¥75、毛利率14.29%→20.00%；这些值由代码生成。
3. 改选方案或修改备注后，必须“保存新版本”，未保存时不能提交。版本号递增，旧参数与历史保留。
4. “查看版本记录”检查不同版本的参数与状态。退出应用再启动，“决策草稿”应保留草稿、版本和申请。

## 提交门禁

“提交模拟审批”只写入本地待审批申请。**没有批准、驳回、改价、预算写入或采购执行。**当前actor是local-analyst，本地单用户演示不证明独立审批身份。

可提交需要：demo数据、模型Reviewer passed、所选方案硬约束通过、当前快照未替换且无质量冲突、导入时间24小时以内、版本创建30分钟以内、规则/报告/参数摘要一致。固定历史演示业务日期是模拟专用例外，不代表实时经营数据。广告方案的花费条件值不是平台真实预算。

以下情况必须阻止提交并显示原因：

- 离线演示、Reviewer needs_evidence/rejected、关键字段缺失。
- TEA库存补货虽测算100件，但覆盖2天而交期5天，不能消除到货前缺口。
- 观察方案、CSV经营数据、过期草稿或过期演示证据。
- 导入修正已替换原记录，或规则、质量、报告、参数摘要变化。
- 另一窗口已经修改版本，继续提交或保存旧版本时返回版本冲突。

Reviewer是否通过受本次模型输出与证据完整性影响，不能保证每次演示均可提交。实际待补证报告显示禁用是正确结果。正向待审批、重复提交和旧申请失效的确定性验收由隔离协议测试覆盖，不把协议测试说成模型质量证明。

提交相同版本两次应返回同一申请。提交后保存新版本，旧申请显示“已被新版本替代”；新版本需要重新校验与提交。导出原调查JSON应包含关联草稿最近30个版本及旧申请状态。
