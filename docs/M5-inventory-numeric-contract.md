## 库存数值契约

库存调查的 `summary`、假设、未知项、替代解释和方案理由改为定性文本，模型 `observations` 必须为空；含阿拉伯/全角数字或经营中文数词的输出被拒绝并按原预算纠正。Reviewer 理由也使用定性契约，不复述数量。

代码核验冻结字段与派生指标、四种工具返回、证据 ID、冻结 Case 以及条件方案之后，生成现存、占用、即时可售、在途、销量、窗口、日均、覆盖天数、交期、及时在途、目标库存和补货草稿量。工具缺失、范围错配、指标或方案篡改时不生成报告。零/缺销量保持补证，不能写成零天覆盖或自动补货。

日均销量和覆盖天数保留整数分子/分母，近似值明确标注；件与天分开，不能把在途算成即时可售。目标库存改用 BigInt 分数向上取整：`ceil(7/3×27)` 必须为 63，原浮点链路可能误取为 64。规则和交期假设没有因此变成需求预测。

库存数值审计随报告持久化与导出；Reviewer 看到的事实观察与保存版本一致。报告通过不改变方案硬约束：默认交期超过库存覆盖时，补货方案仍不可执行。真实采购、到货或收益不会由报告生成。

七项新增领域测试覆盖模型数字表面、事实单位/分数、工具/身份/方案篡改、零/缺销量、浮点取整、复核与持久化一致性及更正预算。真实模型评测契约升级为 `retail-live-eval-v4`，新增库存事实核验评分；Skill 为 1.4.0。新 v4 批次已独立执行：毛利 5/5、库存 4/5、广告 5/5，越权观察 0，达到预设每场景至少 4/5 门槛；库存首轮 needs_evidence 原样保留，见 [第四批完整证据](M5-live-evaluation.md)。

## 桌面回归发现的两项修复

完整桌面回归先发现分页投影只监听经营行，没有监听批次元数据：导入时间更正后，页面会保留旧的时效信息。补齐 `retail_batches` 与 `retail_batch_rules` 的变更失效触发器，并在旧投影首次升级时失效一次。专项同时核对记录时间、批次历史和旧缓存升级；来源与历史仍是权威数据。

后续回归又发现只读自动刷新会清掉用户操作反馈，且独立业务页仍会发起无关毛利读取。现在只读读取保留反馈，毛利分页读取限定在总览/异常/数据页。随后又发现后台读取期间新 CSV 预览请求会被直接丢弃；共享请求改为串行 Promise 队列，保留旧查询世代校验，不让后台读取吞掉用户操作。各次失败均保留在本轮验收归档，不能以单测通过掩盖 UI 问题。

修复后的领域、telemetry 与翻译检查器回归为 242/242、1815 次断言。十万行毛利 30 次新 worker 查询 p95 为 793.332 ms，导入 47.821 秒；仍是预热 OS 缓存下的限定路径，测量期间存在本机开发任务，不据此声称比上一批更快或覆盖库存/广告同规模。

最终原生桌面初次 56 项、重启 16 项通过，包含三场景模拟执行、补偿、UNKNOWN 对账和 Case。原测试驱动在只读刷新期间直接点击禁用的调查按钮，已补“按钮实际可用”的条件等待；未用固定延时或放宽业务断言绕过。功能提交 `d619635` 的 [GitHub CI 39109306429](https://github.com/RXQ6/Merqo/actions/runs/39109306429) 已全部通过。
