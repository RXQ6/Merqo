# M4 调查复核阻塞处理与真实模型验收

日期：2026-10-17。本轮补齐桌面失败态与处理路径；不代表完整 M4、M5 或 P0 发布验收通过。

## 交付

- 草稿保留原调查 ID，可查看准确的模型、来源、Reviewer 结论及完整意见。离线、待补证、驳回分别提示，不再混成一条原因。
- “查看原调查与补证”仅按 ID 读取原调查，不自动调用模型；不依赖最近 50 条列表命中。读取受当前 workspace 数据库限制，不接收路径或任意查询。
- 调查页提供“更新或补充证据”。补证后从当前快照重新选择；点击“重新进行模型调查”才明确发起新调用。新报告须重新生成草稿；旧草稿、申请与批准不迁移。
- 从 Case 发起后续调查后，桌面打开返回的精确 run，不再因进入页面额外发起模型调查。
- 毛利工具明确整数分、SKU 销售件、单件与快照合计口径；报告要求注明单位。Reviewer 分开判断报告证据与方案条件约束，不把数值 passed 当作真实收益或业务授权。缺证/驳回不会被上调。
- 沿用原桌面外壳及样式。真实经营平台未接入写入。

## 用户验收

1. 在被阻断的草稿下查看“关联调查与复核”，应看到来源和具体复核意见。
2. 点击“查看原调查与补证”：打开相同 run 的原报告；没有自动模型调用。
3. 若为离线，明确点击“重新进行模型调查”；若为待补证，先检查未知项和复核意见，必要时更新数据并在当前快照开始调查。配置问题按错误提示在设置中处理。
4. 仅当新报告 Reviewer 通过且方案满足硬约束，点击“生成决策草稿”，再保存、提交模拟审批。旧草稿不会因新报告通过而自动获准。
5. 使用一条驳回或待补证报告保存草稿，提交按钮仍禁用；尝试服务调用也应拒绝。

审批与复盘由自动化脚本的本地模拟角色完成，不代表真实人员身份或实际经营效果。模型调用部分未通过桌面按钮；桌面完整调用链另用本地协议 fixture 验证，二者不得混为真实模型 UI 全链路证明。
