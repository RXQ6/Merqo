# Merqo 经营知识中心：W1—W3 开发与验收

日期：2026-10-22。目标版本：本机 beta.9。公开 GitHub 安装包当前仍为 beta.8；本文不代表已发布新安装包，也不代表已连接真实飞书知识空间。

## 软件入口与业务链路

左侧「分析与跟进 → 经营知识中心」。原场景标签、经营方法、专题和冻结案例仍通过「经营案例与原有标签」访问；原条目也可在新中心阅读。文档维护后保留其原类型与 ID。

发现异常 → 调查记录查看适用知识并引用具体版本 → 参考方法创建/打开有原调查证据的业务任务 → 完成后整理方法或案例草稿 → 人工编辑与发布 → 实体上下文助手读取适用的知识版本。

## W1：知识中心

- Markdown 正文、标题/列表/表格预览；可导入 `.md/.markdown/.txt`，导出 Markdown。
- 内嵌 PNG/JPEG/WebP 插图，每张最多24KB。文档最多60000字符；正文和内嵌图合并计入。外部图片不自动请求，提供打开来源入口。
- 经营规则、处理方法、业务资料；原经营案例保持冻结记录，允许整理为新草稿。
- 标题和正文、店铺、SKU、目录全文子串搜索；目录筛选；每页30条；草稿、发布、停用、回收站。
- 场景、店铺、商品、生效与截止日期；草稿和停用条目不进入新引用。
- 最近阅读、失效/来源异常维护提示、最近100个历史版本；恢复历史内容会新增版本，不覆盖历史。
- 单工作区最多500个知识条目、20个外部来源。回收站为软删除，不清除历史证据。
- 本地“发布”是操作者维护状态，不冒充多人审批或可信身份。

## W2：调查、任务与助手

- 调查按真实业务场景、店铺、SKU 和业务日期匹配已发布知识，展示匹配原因；单次最多30个冻结引用，候选列表最多20篇。
- 引用可在模型报告之后补充，因此明确作为调查附加参考，不改写原模型结论。Markdown/JSON 调查导出包括知识版本及正文。
- 从方法选择适用的已有报告、负责人和截止时间，事务内冻结调查引用、创建/复用原调查任务及知识关联。任务仍遵循原有按来源幂等规则，已有任务不会凭空变成新任务。
- 完成任务可整理为方法草稿；已归档案例可整理为 Wiki 草稿。草稿保留任务/案例来源及人工分析/模拟、真实效果未验证等限制。
- 已归档案例额外冻结其原调查的 Wiki 引用；文档以后更新或停用不改写旧案例。
- 实体助手在提问时冻结适用知识（最多10篇、合计50KB），只接受当前冻结 Wiki/证据 ID。原事实卡与知识区分，知识不代替订单、成本、库存数据，也不构成执行授权。
- Wiki 为不可信参考资料：Markdown 不执行 HTML 或工具；助手沿用无工具、无文件读取、无业务执行的隔离模型流程。

## W3：两类只读来源

### 通用 Markdown 文档源

提供一个 HTTPS JSON 清单，可放在自己的文档站/静态站点。不是任意 Wiki 网页爬虫，不会自动读取浏览器登录状态。

```json
{
  "version": 1,
  "documents": [
    { "id": "margin-sop", "title": "毛利异常排查", "url": "./margin-sop.md", "directory": "经营方法" }
  ],
  "next": null
}
```

清单和 Markdown 文档必须同域；支持相对地址与 next 分页。最多20页清单、500篇文档。可配置 Bearer Token。公开 HTTPS 地址不带用户名、密码或查询参数；不访问本机/内网地址，不跟随重定向，不向其他域转发凭据。

### 飞书知识库

配置企业知识库 HTTPS 地址、App ID、App Secret、空间 ID、可选目录 node token。使用自建应用 tenant_access_token，只读遍历知识目录并读取 docx 的 raw_content。API 按[飞书 Wiki 节点列表](https://open.feishu.cn/document/server-docs/docs/wiki-v2/space-node/list)、[自建应用访问凭证](https://open.feishu.cn/document/server-docs/authentication-management/access-token/tenant_access_token_internal)实现。

需要应用具有知识库读取和文档读取权限，并能访问相应知识空间。首版保留 docx 文本，不还原富文本样式；表格、多维表格、旧版文档、图片及附件不导入，跳过数量单独展示。最多500篇 docx、1000个节点、100次目录分页请求，可缩小同步目录。

### 同步、失效与凭据

- 清单计划、每篇处理序号、计数和错误持久保存。文档落库和断点递增同事务，重试继续原计划；重新扫描重建计划。
- 内容/标题/目录/原文地址/适用场景未变，不生成新版本。当前实现仍需读取正文核对摘要，未声称支持远端 ETag 或只下载变化内容。
- 只有完整同步成功才处理清单中消失的文档：新增停用版本，保留历史。中途失败不会把未遍历到的文档当成已删除。
- 来源失败或停用后，不纳入新的适用知识；旧引用保留，并提示当前来源状态。它无法保证同步间隔内立即察觉远端撤权。
- 每个工作区同一时间一个 Wiki 同步，支持手动、每小时、每天；软件关闭期间没有后台保证。同步失败暂停自动重试，需手动核对后继续。
- Secret 只保存于原有本机凭据管理器，不进入来源列表、任务、文档或模型上下文。业务加密备份扩展覆盖 Wiki 凭据；恢复工作区锁定外部连接操作，需正常工作区重新配置。
- 本轮不向外部 Wiki 写入。案例发布到外部系统不在只读 W3 中；本地案例可导出 Markdown 后人工发布。

## 数据升级

调查数据库 schema 10 → 11；升级前创建备份。Wiki 文档沿用 wb_library/versions，新增引用、来源、同步任务和最近阅读表。完整经营备份与恢复同步支持新 schema；不新增未被备份覆盖的独立业务数据库。

升级后的同一工作区不能交给 beta.8 继续打开；若需回退，应使用升级前备份或独立旧配置。不要同时用两个版本操作同一工作区。

## 验收与边界

源码首次桌面验收已覆盖 W1 文档与版本、W2 引用与方法任务、W3 Markdown 中断后续传、飞书 token/目录/docx 同步、凭据不回传、1440/800窗口。

脚本：`scripts/merqo-wiki-check.cjs`。接口数据在隔离测试进程 HTTPS 边界模拟，应用 IPC、凭据管理、Bun worker 和 SQLite 为真实代码路径。不会把测试 Secret 放进用户配置或发布包；没有调用用户真实飞书空间。

完整回归、最终本机包验收与截图记录会在交付时列入同日期验收报告。真实飞书权限和实际网络下的首次同步仍需用户配置后验收；不冒充已完成。
