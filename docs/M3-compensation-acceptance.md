# M3 补偿申请、再审批与模拟恢复验收

后续执行批次、待确认恢复与部分成功切片见[M3批次验收](M3-batches-acceptance.md)及[验证记录](M3-batches-verification.md)；下文保留本轮单动作补偿的历史范围和结果。

## 启动

退出旧 RetailPilot 窗口，执行：

```powershell
cd "D:\helson-skills\craft-agents-oss-main\retailpilot-agent"
bun run retail:start
```

修改源码后先 `bun run retail:build`。本轮沿用桌面布局，新增“补偿记录”，入口也在执行成功回执旁。

## 预算恢复：完整正向链路

1. 先按[模拟执行验收](M3-execution-acceptance.md)完成广告调查、草稿、批准及模拟预算1000→900元。必须是演示来源、模型Reviewer通过且约束可行；CSV和离线演示不能绕过门禁。
2. 在“执行记录”选择该成功回执，点击“申请补偿”。填写非空理由并生成申请。
3. 应显示补偿前900元、拟恢复1000元、原成功回执绑定、当前模拟目标版本1、证据导入时间和新申请30分钟有效期。原批准不会自动批准补偿。
4. 填写补偿审批理由，可先驳回；修改申请理由并“保存补偿新版本”，旧结论仍在版本记录，新版本须重新审批。
5. 点击“批准补偿”，勾选仅执行本地模拟补偿，执行。应出现补偿成功回执、目标版本1→2、900→1000元及回读核对一致。
6. 点击“重新核对补偿”，保留新的核对记录。原预算执行回执及原始经营快照不变；原执行回读可能报告当前值已变化，这是历史执行后的补偿结果，不是原回执被改写。
7. 重启后进入“补偿记录”，批准/驳回理由、版本历史、补偿回执及回读保留；成功项不能再次执行。报告Markdown/JSON导出包含关联补偿申请、历史、审计与回执。

## 补货取消

使用“载入补货执行演示”的1天交期样例完成20件待受理补货请求，再从成功回执申请补偿、重新批准及执行。应显示本地请求cancelled、待受理数量20→0；可售仍40件，原始现存和在途都不变化。

仅支持pending取消。请求已受理、已取消、状态不明或目标被后续动作修改时，禁止直接取消并转人工。旧v3模拟器只创建pending请求，因此无显式状态字段的旧回执仍可按其原语义取消；新执行明确记录pending。

## 毛利恢复：必须验证阻断

默认毛利样例把商家券20→15元后达到20%阈值。恢复至20元会回到14.29%，应显示低于毛利下限并阻断批准，不能因为“补偿”绕过规则。若成本等证据经过实际核验修正，使恢复仍符合下限，可保存补偿新版本并重新审批；不能为了演示随意修改真实业务数据。

## 冲突、失效与恢复

- 补偿绑定原成功回执和当时完整模拟目标版本。后续动作改过目标，即使值又变回相同，也不能覆盖；保存新版本不能绕过此限制。
- 补偿申请过期、来源证据或规则变化后失效。发现失效会落盘，时间或证据恢复不能让旧批准复活；需新版本再审批。
- 原批准过期不抹掉历史执行；补偿是独立的新授权，必须使用当前有效证据与新的批准。
- 重复点击或响应丢失，先刷新补偿记录确认。已成功只返回原回执，不二次恢复；失败回滚效果，记录原因，门禁仍有效时才可手动重试。
- 回读有差异时保留记录并人工核查，不自动覆盖或反向再执行。

## 边界

仅本机单用户角色演示，没有生产独立审批身份。只操作隔离的模拟表，不连接真实ERP或广告系统。本轮补齐单动作补偿；多动作部分成功、外部结果未知、经营效果复盘、Case、调度和发布验收仍待后续。

决策库升级v4，v1-v3升级前生成 `<业务库路径>.investigations.backup-v<原版本>-<UUID>.sqlite` 一致性备份。原批准、执行及回执保留；备份仍为人工恢复材料。
