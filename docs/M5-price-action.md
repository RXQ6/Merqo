# M5 D01：直接 SKU 改价闭环

2026-10-19 后续实现。独立动作 `set_price`，与现有 `reduce_coupon` 分开调查、复核和审批。

- 用户从毛利调查页选择“进行直接改价调查”。动作随调查冻结，暂停/恢复与 MCP 均沿用；不能借减券报告直接生成改价审批。
- 代码按冻结成本与毛利下限，向上取整计算满足目标的最小标价；券、满减及补贴保持不变。默认涨跌幅上限 20%，现已支持[规则配置](M5-business-policy.md)。金额范围沿用导入契约，会员价格需单独策略而被阻断。
- 价格事实由确定性代码核验后呈现；模型只能给定性说明。模型返回的价格或动作篡改不能覆盖测算。
- 草稿绑定原价、目标价、券、证据、报告、规则、期限和摘要；审批后模拟执行并回读。价格与券动作共享商品资源版本；冲突动作不能覆盖已执行结果。
- 成功执行幂等，保持原业务快照不变。补偿需新申请、新审批；恢复原价若低于当前毛利下限则拒绝。安全恢复的成功回读已在领域集成测试覆盖。
- 决策数据库提升版本，升级前备份；后续规则配置继续提升为 v8，旧程序不得降级操作。

## 验证

`price-action.test.ts` 覆盖整数取整、幅度与无效价格、原券不变、审批执行回读、幂等、共享目标冲突、成功补偿、低毛利补偿阻断，以及 CSV/离线/篡改拒绝。实际 MCP 增加改价动作与替换动作拒绝检查。

原生 Electron 使用本地模型协议夹具完成 UI 调查→改价事实→草稿→审批→执行回读→不安全补偿拒绝→真实退出/重启。最终结果：[native-result.json](verification/price-action-2026-10-19/native-result.json)；原始 trace/截图在结果引用的 `artifacts/price-action/2026-10-19T05-42-46-432Z/` 目录。

验收脚本首次等待初始调查时间不足，第二次把事实列表误当表格，第三次未兼容重启恢复经营界面，失败日志均保留；最终修正定位与状态等待后通过，没有跳过断言。这些为测试脚本问题，不能当作新增产品功能。

该实现限定本地模拟，不构成真实平台改价能力。尚未生成或发布新安装包，整体验收仍受其余固定剩余项限制。
