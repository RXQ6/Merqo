# 晨会与经营经验增强交付

路线：发布 beta.11 → 本机安装升级验收 → AI 晨会摘要 → 商品/案例分类 → 可解释案例匹配 → 使用反馈排序 → beta.12 回归与发布。

## 已实现

| 位置 | 使用方式 | 行为 |
| --- | --- | --- |
| 经营总览 → 经营晨会 | 生成 AI 摘要 | 使用已配置模型，读取冻结晨会前二十项元信息，生成定性建议和原事项引用；不发送原始交易记录 |
| 同上 | 编辑、保存、导出摘要 | 保留原始 AI 内容与修订历史；TXT 导出已保存版本和来源；失败可重新生成，规则晨会继续可用 |
| 经营总览 → 商品经营档案 | 商品品类与标签 | 按独立商品范围保存品类和标签，同名商品不自动合并 |
| 商品档案、调查、决策 → 参考经营案例 | 维护案例分类与适用条件 | 品类、标签、异常类型、适用日期、条件、排除情形及停用；保留分类版本历史 |
| 同上 | 查看匹配说明 | 解释场景、商品、店铺、来源、品类、异常、标签匹配；同时提示日期、规格、来源等差异 |
| 同上 | 有帮助 / 不适用 | 当前商品范围、当前分类版本反馈分别调整 +5 / -10 分；可关闭反馈调序；分类变化后旧反馈保留但不参与排序 |

匹配是明确规则，不是成功概率或模型训练。条件与排除情形须人工核对。停用或超出适用日期的案例只在维护模式出现，不能新引用。既有调查及任务保存的案例分类版本保持冻结。

摘要只允许定性正文及提供的事项标识；无法核验格式、数值输出、未知引用、超时均记为未完成。人工修订明确标注。生成任务与编辑有版本保护，重启后保留已保存记录。

## 仍需外部环境

真实模型的经营摘要质量、真实平台授权和数据完整性、干净 Windows 虚拟机及跨版本 Windows 验收仍需真实环境。抖店、安卓不在本轮范围。审批和执行仍是本地模拟；本轮没有真实平台写回、多用户权限或关闭应用后的后台服务。

数据库 schema13；首次升级自动保留迁移前备份。请勿以旧版本直接打开已升级工作区。
