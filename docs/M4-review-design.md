# M4 复盘与 Case 设计

本轮实现成功本地模拟回执 → 观察记录 → 人工复核 → Case → 后续调查冻结检索。沿用原桌面主题、字体和双栏记录布局，从执行记录进入，不重新设计应用外壳。

仅支持合成业务时间回放：基线取原调查冻结快照，观察窗为紧邻的同长度业务日期窗口（日毛利为1日）。这不是实际模拟执行时间之后的真实经营观测；回执墙钟时间与合成业务日期分别展示。观察窗未结束不能复核；没有可比记录为待补证。内置回放保持销量/库存/广告效率原值，不伪造收益。上传CSV必须明确声明为模拟观察，使用既有字段契约，不写入经营快照；整份限定一条有效记录，错误拒绝，先预览再确认。

复盘冻结原run、job、批准、回执、证据摘要，后续观察按版本追加历史。严格核对店铺、渠道、SKU、规格、币种、仓库/Campaign、相邻等长窗口、归因与原对照值；未知保留为null。确定性代码计算前后值和差值，不推导因果。复核须填写结论及同期活动/干扰因素，绑定预期版本与观察摘要；只允许“仅作比较”或“无法判断”。已复核记录不可覆盖，生成唯一只读Case；补偿历史在读取/导出时另行关联，不能擦除原执行。

Case检索严格限定workspace、店铺、渠道、SKU、场景、仓库/Campaign及规格；只供demo来源使用。结束日期不得晚于新调查业务日期，复核时间不得晚于新调查开始时刻。检索至多5条，在调查创建事务内冻结，后续Case变化不回填旧调查。结果随retail_get_sku_context只读工具返回，沿用四工具面；Case自身ID、来源和引用链随上下文保留，模型引用该工具evidenceId，Case不是指令或批准。

决策库v6升级前备份v1-v5；追加复盘版本与Case索引。Case无需向量库。测试覆盖三场景、缺数、范围/时间/归因错误、并发复核、幂等、重启、迁移与MCP冻结校验。当前交付不含真实业务效果证明、定时观察、生产身份或模型Case质量评测。

已复核的内置回放提供显式后续调查入口：由服务端从冻结观察导入一条demo快照，开始模型或明确的离线调查。此独立操作才会追加演示来源，不自动执行。用户上传记录没有该入口。关联补偿申请及成功回执在复盘页另行展示。
