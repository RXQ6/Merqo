# 抖店只读请求传输准备

这是 beta.5 打包后继续开发的源码模块，不是已连接店铺的功能。

`doudian-client.ts` 复用既有固定正式域名、只读方法和签名构造器，新增显式单页 HTTP 发送、超时/取消、禁止重定向、HTTP 与平台响应校验。仅校验 `code=10000` 和 `data.page/size/total/shop_order_list` 传输结构，不猜订单财务或售后字段。平台错误不回显原始响应或完整含 Token URL，日志只能使用脱敏审计。

调用成功为 `received_unmapped`，返回页数、条数、平台声明总数、接收时间及响应摘要；这不代表字段已映射、导入成功或数据完整。没有自动重试、自动翻页、同步水位推进、原始订单持久化或账本写入。取消后不发送请求；网络失败保留调用方原有位置。429和502/503/504只标注可重试，由后续同步调度处理。

测试使用内存中的合成 HTTP 响应，无真实平台请求。请求构造和传输共6项通过、76断言，覆盖签名只读请求、成功页、认证/限流/服务错误、平台失败、非法页码/页大小/总数、无效 JSON、网络异常、主动取消与超时。领域类型检查通过。首次测试中审计状态 `received_unmapped` 与被禁止的样本文本发生断言误匹配，已改为检查原始业务值；未改产品逻辑迎合错误断言。新类型检查发现旧请求测试的 fetch mock 缺少 Bun `preconnect` 类型，已修正测试替身。验证日志见 `docs/verification/doudian-client-2026-10-20/`。

仍需开通应用和店铺授权，才能验证凭据、实际返回结构、分页/增量、字段映射与去重、支付/售后补齐和后台对账。未将单页返回或列表总数视为财务事件完整性证明。

官方依据：[订单列表接口](https://op.jinritemai.com/docs/api-docs/15/521)。授权联调时应再次核对接口权限及返回结构。
