# 抖店接入准备

2026-10-20：用户选择保留 CSV 本地版并准备抖店接入，确认尚未开通应用。当前阶段为离线准备，未获得店铺授权、未调用真实 API、未同步真实订单；不能标为平台接入完成。

## 已准备的代码

`packages/retail-domain/src/adapters/doudian-request.ts`：仅供主进程或 Worker 使用的订单只读请求构造器，固定正式域名和 `order.searchList`，使用更新时间、升序、从0开始的分页，单页最多100。按排序后的 JSON 构造 HMAC-SHA256 签名及 POST 请求；不接受任意 API 方法。没有网络发送、Token 获取或持久化功能，不向 renderer 或通用 Agent 暴露密钥。

配套2项离线测试：排序稳定性、独立 .NET 生成的合成签名校验值、分页影响签名、参数限制及 fetch 零调用。校验值不是平台官方认证向量；离线通过不能代表平台鉴权成功。日志只能记录返回的 `audit`，完整请求 URL 含 Token，不能写入日志、证据或聊天。

后续源码新增 `adapters/doudian-client.ts`：显式调用的单页只读 HTTP 发送器，校验平台成功码及页码/大小/总数，区分 HTTP、平台、网络、取消和响应错误；请求超时、拒绝重定向，不自动重试或推进同步水位。只返回传输结果和脱敏审计，订单字段保持未映射，不写交易账本或持久化原始订单。原始响应仅供服务端后续字段映射使用，不能直接进入 UI、日志或导出。采用合成响应验证，尚未进行真实鉴权。这一后续模块不在 beta.5 打包源码提交 `d147773` 内。

## 官方依据

- [订单列表正式接口](https://op.jinritemai.com/docs/api-docs/15/521)：更新时间筛选、页码从0开始、单页上限100。上线前需在应用后台核对所获场景包权限及当前版本。
- [官方签名和 POST 示例](https://op.jinritemai.com/docs/guide-docs/10/812)：采用秒级 timestamp、HMAC-SHA256 和业务 JSON 请求体。旧页面中的文本时间格式不作为本实现的依据；联调时仍需以当前应用支持的协议和响应核验。
- [API 调用指南](https://op.jinritemai.com/docs/guide-docs/10/23)：总体调用流程。部分文档依赖动态页面，正式字段映射以开通后的当前文档及脱敏响应共同确认。

## 开通后的一条实施线

确认应用类型与店铺所有权 → 创建应用并申请订单只读权限 → 店铺授权和安全保存密钥 → 小时间窗拉取一页 → 脱敏响应核对字段 → 分页及增量补拉/去重 → 来源与水位对账 → 生成交易导入预览 → 用户确认入库 → 比对抖店后台 → 扩展商品/库存及售后来源 → 单独评审真实写入。

当前需要店铺方在官方后台完成应用创建和授权。自用应用还是服务商应用尚未确定，不替用户注册、提交资质或申请权限；无需在聊天中发送 App Secret 或 Token。后续密钥接入复用项目安全凭据服务，禁止写进普通 JSON 配置或导出文件。

## 字段与记账准备

| 本地需要 | 接入时必须核对的来源证据 | 当前处理 |
| --- | --- | --- |
| 店铺、订单、订单行、SKU及规格 | 平台原始 ID 与显式商品映射；不能只按名称匹配 | 未拿到脱敏响应，不猜字段路径 |
| 下单/支付/发货/取消/退款/实物退回 | 各事件实际时间、数量、状态及不可重复标识；订单更新快照不等于完整事件流 | 只读订单列表不足以直接生成全部事件，售后和支付明细另核对 |
| 商家优惠、平台结算补贴 | 明确承担方及行级分摊；来源已分摊时保留原结果 | 不因字段含“补贴”就加商家收入；缺口阻断金额结论 |
| 成本 | ERP或商家确认的同规格、同时间成本 | 不能从销售价推断；缺成本不算毛利 |
| 现金退款与实物退回 | 退款成功和实物入库分别取证 | 不因退款成功就回补库存 |
| 来源、水位和完整性 | 请求窗、页码、返回数量、接收时间、对账结果及延迟说明 | 页码拉完不等于售后完整；不冒充平台完整截止证明 |
| 广告 | 独立广告系统授权及归因口径 | 抖店订单权限不视为广告权限 |

第一版不采集买家姓名、手机号和详细地址。平台错误响应、过期授权、限流、超时、中断续传、重复页、页间变更、跨期退款、退款差价和换货关联须有联调记录后才能验收真实同步。真实调价、预算和补货写入、多人审批身份及业务收益观察仍是独立 P1 任务。
