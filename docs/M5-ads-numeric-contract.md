# M5 广告数值与证据披露修复

本轮修复首批真实模型评测中 `100000` 分被写成“10万元”的问题。实际值为 **¥1000.00**。该错误来自调查模型的自由文本，Reviewer 也沿用了错误，说明单靠模型复核和可解析引用不足以保证金额正确。

## 数值路径

`ads-numeric.ts` 从冻结 `SignalRecord` 与四种只读工具生成广告事实：观察/对照花费与归因成交额、ROAS 及其相对变化、点击/转化数与点击转化率、条件方案花费/假设成交额/ROAS。金额保留 `CNY_minor` 原值，展示时由代码换算为元，并同时标注分；比例基点除以百显示百分比，ROAS 作为无量纲比值显示，不作金额或利润解释。

例如合成 TEA-500 的花费为 ¥1000.00（100000分），归因成交额为 ¥1800.00（180000分）；条件方案为花费 ¥900.00、假设成交额 ¥1620.00、ROAS 仍为 1.8。这不是需求、利润或收益预测。

事实生成前重新计算冻结字段的指标，逐个核对 health、sku_context、campaigns、simulate_actions 的完整 payload、证据 ID 与冻结 Case，并核对代码方案。缺少、篡改或不一致的工具结果直接阻断报告，不进入 Reviewer。合法缺字段保留 `null/待补证`，不填成零，现有证据缺口继续阻断可执行方案。

广告调查模型的 `observations` 必须为空；代码在复核前替换为已核对事实。摘要、假设、未知项、替代解释和方案理由采用定性文本契约，拒绝数字和所覆盖的中文经营数词；Reviewer notes 也使用相同格式约束，避免在复核意见中再次自行复述金额。格式纠正仍受原有两次调查、一轮 Reviewer 纠正上限约束；不静默删改错误文字或强行把复核结论改为 passed。文本正则不证明已理解或拦截任意自然语言数值表达，语义正确性仍需 Reviewer 和更广泛的评测。

`adsNumericAudit` 为可选报告字段，保存版本、单位、数值、引用和计算完整性；重启与 JSON 导出保留。已有历史报告不重写。UI 与 Markdown 的观察区域直接显示代码观察，无需新增一套模型金额展示。

## 披露和复核范围

毛利证据清单按实际冻结 Case 是否存在分别说明“为空，无历史对照”或“已有合成比较，不证明因果”，两者的 causalReady 和 realExecutionReady 均保持 false。

库存/广告在复核前加入同样准确的 Case 披露，并把实时状态、权限和独立审批标为执行边界。Reviewer 按报告实际主张区分同口径快照描述、条件算术、经营建议、因果及真实执行：前两者不自动获得后三者的证据或授权；缺计算口径、无依据的归因与承诺仍应拒绝或补证。系统未自动覆盖模型的 needs_evidence/rejected。

领域 Skill 资源重新生成并升至 `1.2.0`，包括广告空 observations 与定性文本要求，以及 Case ID 的展示边界。MCP 回归验证实际读取的新资源。真实评测契约升级为 `retail-live-eval-v2`，增加广告 audit/观察精确匹配与模型定性文本检查，源码摘要纳入三个实际 Skill 文件及新数值模块。

## 验证与后续

本轮领域及 telemetry 合计 **226 项测试通过、0 失败、1684 次断言**，领域/Electron 类型检查、真实 stdio MCP 回归、完整 `bun run electron:build` 通过。新增回归使用首批原始错误，覆盖各模型文本字段、金额换算、缺数、篡改工具、预算、Reviewer 数值输出纠正、拒绝结论保持、持久化与最终披露一致性。
