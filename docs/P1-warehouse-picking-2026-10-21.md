# 按效期拣货建议与确认预占

开发版入口：经营分析 → 库存与广告 → 仓库收发存与调拨 → 按效期拣货与预占。

填写明确来源、店铺、仓库、SKU、规格、人工订单引用和“本次新增预占数量”，生成建议。可使用“使用上方仓库范围”复制三个范围字段；没有填写的范围不自动放宽到全部。拣货按服务器当前时刻计算，不随上方历史截止日期回看。

## 分配规则

- 从完整仓库事件账本重放当前已发生事件，不限于上方展示的100库存桶。
- 只选相同来源、店铺、仓库、SKU及规格的可售状态批次。
- 可分配数量扣除已有预占，排除过期、效期未知、隔离和报废库存；不把尚未发生的未来入库用于当前预占。
- 对效期明确且有效的批次按先到期顺序选取；相同效期按批次ID字典序固定顺序。
- 显示需求、已知可分配、缺口和排除数量。未知效期不参与全局先到期判断，不能据此声称所有库存都已核清。
- 不足时不自动部分预占；未知效期可能影响缺口时标为待补证。一份建议最多100批次，账本仍受50000事件上限约束。

生成建议不会改变库存或预占，只保存短期预览。人工核对并勾选后，系统原子写入每个批次的本地预占事件。现存不变，不自动出库、发货或调用WMS。

## 确认及留存

预览绑定完整库存事件、来源证据、输入及当前业务日，10分钟有效。库存或来源变化、跨业务日、过期都须重新生成；未来已有出库等承诺导致新增预占不满足事件链时直接阻止。确认一次只能全批成功，不能部分写入。

重复确认同一预览返回原回执，不再次扣占；即使短期预览已经清理，已成功回执仍可在重启后核对。短期预览表最多保留1000条未过期记录；过期预览可清理，不删除仓库事件或回执。回执和预占属于原交易SQLite数据库，随经营加密备份恢复。

每次重新生成并确认都是明确的新增预占，不把人工订单引用当作真实订单唯一性证明，也不会把“同订单引用”自动合并成目标总量。后续释放及关联发货沿用既有预占事件契约。
