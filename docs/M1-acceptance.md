# M1 促销毛利场景验收

本轮是实际可操作的经营数据与规则版本，不需要模型连接。Agent 调查、方案草稿、审批、改价、调预算、补货执行尚未实现。

## 1. 打开新版本

先关闭之前运行的旧 RetailPilot 窗口，然后在 PowerShell 执行：

```powershell
cd D:\helson-skills\craft-agents-oss-main\retailpilot-agent
bun run retail:start
```

依赖与开发构建已生成。重新复制源码到其他机器时，先 `bun install --frozen-lockfile`、`bun run retail:build`。当前验收的是开发构建，不是安装包。

预期：直接进入“经营总览”，左侧有经营总览、异常中心、数据与导入。无需停在模型欢迎页。模型配置与通用聊天保留在左下角“通用 Agent 工作台”，可通过“返回经营工作台”切回。

## 2. 载入演示数据

点击“载入演示数据”。如果之前已经载入，可在“数据与导入”再次点击，应该提示不重复写入。

预期：

| 项目 | 应看到的结果 |
| --- | --- |
| 数据来源 | 演示数据，明确标为合成静态快照 |
| 商品快照 | 6 条 |
| 毛利预警 | 2 条 |
| 待补证 | 2 条 |
| 正常 | 2 条 |
| 商家商品收入 | ¥7,125.00 |
| 商品毛利 | ¥1,765.00 |
| 完整性口径 | 合计仅计入 4 / 6 条具备完整证据的快照 |

不能把“待补证”两条当作零成本或确定毛利计入合计。演示日期固定为 2026-10-14，不代表实时同步。

## 3. 核对毛利计算与证据

搜索 `TEA-500`，点击该行“查看”。

应看到“桂花乌龙冷萃茶，500ml × 6瓶”：

- 单价 ¥100.00，商家券 ¥20.00，商家满减 ¥10.00，额外平台结算补贴 ¥0.00。
- 商家商品收入每件 ¥70.00，商品成本每件 ¥60.00，商品毛利每件 ¥10.00。
- 毛利率 14.29%，低于 20% 演示阈值，状态为毛利预警。
- 净成交 40 件；现存 120、占用 10、可售 110、在途 60，在途不计入可售。
- 可查看来源、业务日期、导入时间、原始字段、证据记录 ID、导入批次、SHA-256 和规则版本 `retail-margin-v1`，并导出证据 JSON。

关闭详情，分别查看 `SNACK-300` 与 `OAT-1000`：前者应解释成本缺失，后者应解释补贴承担方未知；两者不输出确定的收入与毛利结果。查看 `COFFEE-12`，确认额外平台结算补贴 ¥10.00 只加入一次，商品收入 ¥90.00，毛利率 33.33%。

## 4. 核对异常中心与筛选

进入异常中心，应只有 4 条异常（2 条预警、2 条待补证），不包括两条正常商品。选择状态、店铺、渠道或经营日期，并搜索 SKU，列表应随筛选变化。金额指标按店铺、渠道、日期范围计算；商品搜索与状态用于筛选下方明细列表，不改变上方范围合计。

点击“导出当前结果”，CSV 应只包含当前明细筛选结果，并带证据 ID、快照摘要和规则版本。导出文件中的可执行公式前缀会转义。

## 5. 验证 CSV 导入和错误隔离

打开“数据与导入”，选择项目中的：

`fixtures/retail/import-with-errors.csv`

预期：

1. 自动映射 17 个字段，展示原始数据预览。
2. 总计 3 行，有效 1 行、隔离 2 行；其中 1 行业务键重复，另 1 行币种为 USD。
3. 映射可手动修改。修改后必须点击“重新校验映射”，不能直接导入未校验的映射。
4. 点击“导入 1 条有效数据”，错误行不进入经营记录，隔离原因写入导入质量报告。
5. 进入经营总览，数据来源切到 CSV 导入数据，看到“验收导入店”的 1 条 SKU，收入每件 ¥70.00、毛利率 14.29%。对应合计商品收入 ¥2,800.00、毛利 ¥400.00。
6. 再导入相同文件，应提示“此文件与映射已导入，未重复写入”，行数仍为 1。

演示与 CSV 通过来源选项分开，不能混在同一收入和毛利合计中。

导入表头支持模板英文名或内置中文名，也可手动映射改名的列。CSV 为 UTF-8；最多 2 MB、64 列、每来源最多 10,000 条当前快照。金额必须填整数分，空白金额不会默认为零。`cost_minor` 允许为空并进入待补证；其他必填数字空白会隔离。

## 7. 验证持久化

正常关闭窗口，重新运行 `bun run retail:start`。

演示数据仍为 6 条。切换 CSV 来源后，更正后的 1 条记录及 33.33% 毛利率、导入历史应仍存在。默认来源为演示数据，因此重启后需主动切到 CSV 查看自己的数据。

业务库位于当前 Workspace 的 `retail/operations.sqlite`。正式启动器的默认本机路径是 `.runtime/config/workspaces/my-workspace/retail/operations.sqlite`；实际路径以当前 Workspace 配置为准。

## 8. 自动检查

```powershell
bun run retail:check
bun run typecheck:all
node scripts/retailpilot-m1-e2e.cjs
```

- `retail:check`：领域契约、计算、CSV、幂等、并发导入、修正、来源隔离、导出转义与存储重开测试，以及领域包类型检查。
- `typecheck:all`：基座与 Electron 全项目类型检查。
- `retailpilot-m1-e2e.cjs`：启动隔离 Electron，通过实际页面完成演示、证据抽屉、异常筛选、错误隔离、重复导入、快照更正、禁止操作检查，再重启应用验证恢复。测试使用新建 `.runtime/m1-e2e-*`，不读取或修改正式数据。

报告：`artifacts/m1/e2e-initial.json` 和 `e2e-restart.json`，均应 `ok: true`。截图：`overview.png`、`evidence.png`、`import-preview.png`。日志：`process-initial.log`、`process-restart.log`。这些是本机生成的验收产物，不提交到 Git。

## 范围与已知限制

这是第一条“促销毛利”场景的 M1 数据与规则交付。销售和库存字段参与范围展示及库存解释，尚未实现独立的销量、断货或广告诊断规则。20% 是版本化演示阈值，尚无规则编辑器。静态日期与导入时间不构成实时数据时效保证，不能用于直接改价。

平台补贴字段指额外结算给商家的收入，不能把已经包含在商品售价中的补贴重复填写。商品收入和毛利是简化口径，不含运费、佣金、广告、税费等；不能宣称为净利润或真实业务效果。

不支持远程 Workspace 和安装包场景。当前领域服务依赖源码目录下的 Bun 工作进程；打包、模型调用、Agent 调查与审批执行按后续阶段分别验收。
