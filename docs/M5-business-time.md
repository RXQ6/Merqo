# 业务时间与导入时间分离

日期：2026-10-19。接续 [PRD 追踪矩阵](PRD-traceability.md) F02 / D07 / B1，当前交付为业务日时效与冻结时间上下文，不代表跨场景证据包全部完成。

## 当前行为

CSV 重新导入只改变导入批次，不改变业务日的年龄。审批检查分别校验导入时间和业务日期：导入超过 24 小时仍按原规则阻断；即使导入很新，业务日最晚可能结束时刻距当前已超过 24 小时，也会列出历史证据阻断原因。未来业务日和无效日历日期同样拒绝。历史 CSV 仍允许分析，CSV 的分析用途边界保持。

业务时区固定为 PRD 默认的 Asia/Shanghai。现有 `date` 解释为观察期间的最后一个业务日（含当天）：例如末日为 10 月 18 日、窗口七天，期间是 `[10月12日00:00+08:00, 10月19日00:00+08:00)`；对照窗独立记录。未知窗口保持未知，不推定七天或把缺失当零。

“业务日最晚可能结束时刻”仅用于日期精度下的保守历史判断，不是源系统真实观测时间。源观测时刻统一为 `sourceObservedAt: null`、`sourceObservedAtStatus: not_provided`；不会把午夜、导入或 MCP 读取时刻伪装成源观测时间。时间容限只表示未被该粗粒度规则排除，不证明数据新鲜、窗口已结算完整或可进行因果推断。

合成 demo 仍按合成回放处理，不因历史业务日自动失效；无效/超前的导入时钟检查保持。只提供导入时间的旧内部调用继续执行原导入校验；真实领域记录携带业务行，进入完整日期校验。该兼容调用不证明业务时间已经核验。

## 时间上下文传播

`evidenceTimeContext()` 是纯粹由冻结字段派生的 `business-time-v1` 元数据：业务日期、期间、对照期间、时区、日期精度、导入时间、源观测时刻未知标记，以及相对于原导入时刻的业务时间问题。没有加入动态“当前时间”，因此不会使数值核验在调查和 Reviewer 之间产生不同快照。

三个场景的数据健康工具及 MCP 外层返回该上下文；兼容字段 `observedAt` 仍表示原业务日期，新字段明确其精度，并非时间戳。MCP 的 `retrievedAt` 单独保留为工具读取时间。毛利核验会拒绝被篡改的时间上下文；库存、广告原有完整工具对比同样涵盖新增字段。

审批数据基于冻结调查暴露时间上下文，JSON 与 Markdown 导出附带同一内容；历史原始证据不改写。巡检逐条评估导入与业务日时效，在历史/时间异常 CSV 的结果中给出警示，仍统计完整输入与异常数量。
