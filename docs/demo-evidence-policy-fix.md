# 内置演示数据时效与重新载入修复

日期：2026-10-17。

## 原因

之前把24小时导入时效检查应用到了内置合成样例；同时，相同CSV和映射会被重复导入保护直接跳过。这造成演示过期、再次载入又无法刷新，形成死循环。重复导入保护本身仍适用于普通CSV，问题在于把合成回放当成实时证据来检查。

## 变更

- demo合成来源不按导入时长过期；无效时间或超前超过5分钟仍阻断。CSV的时效检查保留，CSV仍不能进入本地模拟审批。
- 审批与补偿共用时效策略；模型Reviewer通过、关键证据、方案硬约束、当前快照、30分钟草稿/审批期限仍需校验。
- 相同演示内容重新载入时保留真实导入时间，不伪造新鲜度、不重复写入。页面明确说明演示不受24小时限制。
- 当前样例被切换或修改后，显式载入原样例会追加新的证据版本，恢复对应业务键；保留旧批次、行历史、CSV数据及模拟执行记录。旧批准不能因样例内容恢复而复活。
- 内部重新载入参数仅由固定演示入口传入；renderer不能把CSV强制标记为演示。普通CSV导入去重规则未变。
- 决策与补偿策略升级v2。旧策略的未执行草稿/申请需要保存新版本并重新审批；历史成功回执保持有效，不重放。

## 用户操作

1. 关闭旧窗口，从项目目录启动最新主进程：

```powershell
cd "D:\helson-skills\craft-agents-oss-main\retailpilot-agent"
bun run retail:start
```

2. 如要恢复内置样例，在“数据与导入”载入演示数据；补货可在“库存与广告”载入1天交期演示。同内容保留原导入时间，日期没有变化并不表示更新失败。
3. 返回“决策草稿”刷新，点击“保存新版本”，再查看提交检查。
4. 如果仍提示Reviewer未通过，应回调查页进行模型调查，确认报告的Reviewer passed后再生成/修订草稿。离线演示、待补证、原5天补货缺口等不能靠保存新版本绕过。
5. 若确实切换了证据版本，应使用当前样例重新调查，不能继续提交旧证据的草稿。
