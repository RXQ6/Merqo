# 广告退款后归因核对

开发版：经营分析 → 库存与广告 → 广告退款后归因核对，可使用“本页功能”定位。先在交易与退款导入交易CSV，再选择归因JSON，核对声明后保存报告。当前是人工声明的订单关联与结算回报核对，不替代原广告快照、平台ROAS或因果归因。

## 声明与计算

归因文件包含活动投放窗口、店铺渠道、整数分支出、归因天数、退款观察天数、关联完整声明及完整水位；每条关联明确来源、店铺渠道、订单行、触点时间和比例。活动ID、同活动订单行不能重复；同一订单行跨所有声明活动的比例必须正好10000基点，不默默归一化超额比例或隐藏未分配部分。

触点须在活动投放窗口内、早于或等于订单时间，订单与触点间隔不超过声明归因天数。来源、店铺渠道和订单行必须与交易账本精确匹配。缺原单、触点/范围冲突或核对时间早于已知后续事件时，活动金额与比率保持未知，不能用0填补。

每个订单行取当前已导入的累计支付和累计退款，按声明比例分别以整数分分配。尾差用最大余数及活动ID字典序稳定分配；退款分配以该活动已分配收款为上限，防止极小金额尾差产生活动超额退款。多活动的收款、退款和保留结算分别守恒。

- 退款前结算回报 = 分配的支付结算 / 声明投放支出。
- 退款后结算回报 = (分配的支付结算 − 分配的退款) / 声明投放支出。
- 零投放时比率不可计算，不输出无穷大。

例如收款100元、退款20元，A/B比例60/40，投放各10元：A保留48元、退款后回报4.8；B保留32元、回报3.2。实物退回没有实际退款时，不擅自扣掉收入。

## 暂态与声明覆盖

观察期最早结束 = 投放结束日的下一天零点（北京时间）+ 归因天数 + 退款观察天数。达到该时间，订单已结清，且关联明确声明完整、水位覆盖本次核对时间，才显示“按声明覆盖，观察期已结束”。否则为暂态，仍展示已知数值，但不能声称完整或稳定。缺证是另一种状态，不与暂态混同。

这些时间和完整性来自操作人声明，未经平台认证；迟到退款仍可出现，观察期结束不是不可变化的保证。没有未关联订单就不存在的推断；某活动没有任何关联时，收入未知，不默认0。任一活动金额未知，范围金额合计也保留未知。

## 持久化、展示及边界

报告写入交易库的只追加 `ad_refund_reports` 表，冻结输入、最多2000条关联事件、账本摘要及结果；最近5份报告可查看和完整导出。已有报告不随后续导入自动更新，重新核对生成新报告。与既有经营数据库一同加密备份恢复。按已存在的来源/订单实体索引读取，不能以这些有界流程宣称大规模或并发性能通过。

归因JSON最多1 MB、20活动、2000关联；本次核对最多2000条实际关联交易事件。商家结算可能包含交易已声明的平台结算补贴，不等于买家GMV；未扣商品、平台、物流或其他费用，不是净利润。不同活动比例和触点仍为人工判断，不能据此证明广告因果贡献。

页面上方库存/广告快照筛选不自动改变本工具的显式活动范围，报告不改写快照或交易、不调整预算，也不自动送入Agent调查。真实广告平台身份、认证完整性、官方归因去重、跨模型比较、真实平台投放回写仍待接入。验收见[记录](verification/ad-refund-2026-10-21/report.md)。
