# 交易扩展契约（2026-10-20）

在 beta.3 不可变事件账本上扩展，保留既有单次支付 CSV 和冻结记录，不将本地导入解释为真实执行。

分次支付：`paid` 的金额、优惠和平台补贴为本次增量；未结清事件数量填 0，唯一结清事件数量填原订单行全部件数。按发生时间累计 `收款 + 商家优惠 − 平台补贴`，不得小于 0 或超过原行标价；结清时必须精确等于标价，且只确认一次支付件数。未结清不发货，可按实际已收金额退款；后续退款不会重开支付。相同时间的多次支付要求来源给出可区分时间，拒绝猜测先后。

取消：新增 `cancelled`，金额、优惠、补贴均为 0。未结清时只能整行取消，后续不再收款或发货；结清后可取消未发货件数，累计发货与取消不得超过原支付件数。取消不自动生成退款，退款仍以独立现金事件记录。

实物退回：新增 `returned`，金额、优惠、补贴均为 0；只能对已发货件数记录实物退回，不得早于对应发货或累计超过发货件数。退款与实物退回相互独立，不自动增加可售库存。

汇总继续按事件期 / 原订单归属期查询；新增取消和实物退回件数。支付件数只在结清确认时计一次；首付款收入照实计入当期，退款撤销按退款实际发生期计入。保留结算不等于利润，也不代表订单已履约。

换货：新增订单行的 `ordered` 事件填写 `replaces_order_id` 和 `replaces_line_id`，其他事件不填。按同来源、店铺、渠道查原行，按新下单时间核对已实物退回件数，每个退回件数最多被关联一次。导入时加载关联的旧行及其他换货新单，重新校验总量；循环、跨范围、缺原行和超量整批拒绝。新单的下单、支付和退款独立记账，不自动抵消旧单现金。已关联新单即保留关联，不因新单后来取消而自动释放原退回件数。

订单分摊工具：CSV明确订单、行、原标价、参与资格和订单商家优惠/平台补贴；两资金池分别按参与行原标价分摊，整数分最大余数法，尾差按行ID排序。相同订单总额声明必须一致，重复行、超额优惠、无可参与金额拒绝。输出行级结果后仍需填入实际支付事件并通过原有交易预览，不会自动生成收款事实。

本扩展不推断取消时应退多少钱，不支持未结清行的部分取消、混合币种、支付手续费或重新开启已取消行。分摊不核实活动门槛、叠券资格或平台补贴承担方；来源必须明确声明，不将平台快照猜成现金事件。
