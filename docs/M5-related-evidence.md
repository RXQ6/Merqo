# M5：跨场景旁证匹配与冻结

日期：2026-10-19。当前仍为 M5 / P0 收口，本项是 B1 联合证据的第一段实现。

## 已实现

- 真实调查 worker 创建毛利、库存或广告调查时，读取同一经营空间的候选数据；仅保留同 `demo/csv` 来源、店铺、渠道、SKU、业务末日的其他场景记录。
- 核对规格、Asia/Shanghai 业务期间及信号对照期间。缺规格、期间不一致、质量缺口、组合装映射未核验时标记 `context_only`。广告现有结构没有规格，不能推定匹配。
- 同一场景有多个候选时，保留仓库或 Campaign 原字段并要求确认，不自动选择或汇总。每场景最多冻结 20 条，超出明确标记截断；没有候选的场景列入缺失清单。
- 候选保留原记录 ID、批次、批次哈希、规则版本、导入时间及业务时间精度。`aligned` 仅表示已提供字段对齐，不代表完整可信来源或因果关系。
- 关联结果写入调查 JSON，恢复调查及旧报告沿用冻结结果；重新导入不会替换旧旁证。旧版没有该字段的调查保持兼容，不回填今天的数据。
- 复用四工具只读面，在 `retail_get_sku_context` 返回旁证。桌面核对冻结内容及摘要，三个场景的数值审计拒绝替换旁证。旁证不进入当前场景的数值事实卡，也不放宽处置约束。
- JSON、Markdown 导出包含冻结旁证、匹配原因、缺失与截断标记；三场景业务 Skill 更新为 1.5.0，明确禁止跨窗口合并与排他归因。

## 验证

相关回归 **158 项通过、0 失败，1006 次断言**（8 个测试文件）。新增测试使用真实 data worker 创建三场景调查，执行离线报告、源数据修订、持久化重读及导出，并验证篡改拒绝。实际 MCP stdio 检查覆盖三场景桌面连接和替换旁证拒绝。原始记录见 [验证目录](verification/related-evidence-2026-10-19/README.md)。领域与 Electron 类型检查、主进程构建通过；本轮没有修改页面布局。

## 仍未完成

`source=csv/demo` 不是平台或独立数据源身份；批次哈希不是源系统完整水位。源系统观测时间、可靠来源标识和共同水位仍缺失。不同 SQLite 数据库的读取不构成同一时刻的跨库原子快照。现有数据契约也不足以证明利润、库存、自然流量和归因成交之间的完整业务关联。

本轮只完成日期末日严格相同的旁证连接，不补齐历史区间、不自动聚合日利润为周利润，不证明归因完整或因果关系。跨场景联合诊断质量、完整原生 UI、真实业务来源和外部 Windows 环境仍待验收；没有重跑真实模型或十万行性能评测。

下一步：定义可导入、可追溯的来源标识及水位契约，显式补充广告规格/商品映射和共同窗口数据，再推进完整联合调查。新增源码尚未推送或发布为新安装包。
