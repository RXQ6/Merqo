# M3 执行批次与结果待确认

沿用electron-best-practices、typescript-pro、vercel-react-best-practices、frontend-design、sql-pro和playwright-expert规范。原桌面布局不重做；在执行记录内提供批次入口。

批次是2-10个已分别批准的独立模拟动作的不可变集合，不等于一个未经逐项审批的综合方案。限定同Workspace、店铺、渠道；冻结每项版本、动作摘要与批准ID，唯一job归属防止重复编组。逐项独立事务，无跨动作原子性承诺；成功项保留，失败项只能单独重试，仍须当前批准有效。

每项先提交执行意图与15秒租约，再在原执行事务内检查fencing token并写模拟效果/唯一回执，最后单独登记结果。执行中退出或提交后响应丢失会留下running，租约到期变unknown。unknown阻断继续及重试，必须先查询确认。恢复时在IMMEDIATE事务内冻结旧token，再读取原执行账本：存在绑定匹配的回执则确认历史成功；存在本轮失败记录则确认失败；无回执且无失败记录，只有当前local_atomic协议才能根据效果与回执原子性确认未执行并回到ready。过期旧进程不能越过token重新写入。无法验证的回执保持unknown，转人工，禁止盲重试。

批次不自动回滚成功项。需要恢复的成功项仍从原回执走独立补偿审批。批次状态包括ready/running/unknown/partial/failed/succeeded，并保留每项原因、请求号、审计和恢复事件，支持重启及导出。界面超时先刷新；服务端状态不依赖聊天或浏览器内存。

决策库升级v5并备份v1-v4。实际外部平台Adapter尚未接入，不能把本地无回执证明外推为外部未执行；外部写入必须另有查询结果与幂等契约。本切片不实现模型生成多动作方案、真实外部调用或生产多用户权限。
