# 先验收、再开发：2026-10-20 本机记录

基线为已发布 beta.3（源码 `7d20d1f`），本轮为其后本地工作区改动。原 PRD 未改。本报告区分本地源码、桌面、安装和真实平台验证。

## 验收发现与修复

1. 总览未直接展示整个选定范围的业务日期、批次来源和水位，审批页缺少明确的风险及补偿边界。现已补齐，并扩展到库存和广告页面。
2. 首次桌面验收发现 SQL 分组别名与记录 ID 列冲突，同一批次被分成单行。修正为明确批次列分组，增加批次数量回归。
3. 初版解析整列证据 JSON，十万行30次查询 p95 为2320.63ms，未达到2秒要求。改为可重建的批次索引，只读取每个展示批次的一条证据；旧投影自动重建且保留源记录。最终毛利 p95 为722.57ms，库存656.27ms、广告647.10ms，均通过。
4. 新桌面脚本最初监听 Playwright download 事件超时。产品按钮实际触发 Electron 下载；脚本改为监听 Electron `will-download` 和完成事件，使用真实下载文件继续导入。失败结果保留，没有把生成模板字符串冒充按钮下载。

## 后续开发及验证

分次支付结清只计一次件数；取消、现金退款、实物退回分别记账；换货新单显式引用同来源/店铺/渠道原行，不能重复占用退回件数。所有新事件沿用预览摘要、原子导入、不可变历史和双时间视角。

订单分摊采用整数分最大余数法，商家优惠和平台补贴分别守恒，余数按行 ID 排序；来源明确排除的行不参与。嵌套组合树最多6层500子项，每层成本核对，祖先循环、冲突 SKU、缺成本和不一致均不输出利润；完整子树进入冻结证据与数值审计。规则版本提升到 `retail-margin-v6`，不改写旧冻结调查或批准。
